# Conditioned lower-bound generation

This software generates and checks the four lower bounds in the paper:

| Graph | Certified lower bound | Main generated objects |
|---|---:|---|
| DSJC250.9 | 8,277 | Layered/residual duals and six branch trees |
| DSJC500.9 | 29,791 | Residual packing trees, Farkas certificates and conditional weighted-packing trees |
| DSJC1000.9 | 102,344 | Eight conditional rational duals and a size-five packing cap |
| C2000.9 | 381,823 | A packing of 52 size-six stable sets and a covering partition into 52 conflict cliques |

Generation starts from the DIMACS graph files and enumerates the relevant
stable-set families. LP and integer-programming solvers construct candidate
objects. Exact checks against the graph-derived families establish the stated
lower bounds. The six DSJC250.9 trees and the DSJC500.9 trees are generated by
the supplied branching programs; their node bounds use numerical LP solves
followed by exact rational checks. For C2000.9, the integer solver supplies two
positive objects that are checked directly.

The complete integer all-stable-set master is a separate comparison in the
paper. These commands reproduce the conditioned proof, not that comparison.
Upper-bound search is documented in [../UPPER_WITNESSES.md](../UPPER_WITNESSES.md).

The per-instance algorithms and source map are explained in
[GENERATION_WORKFLOW.md](GENERATION_WORKFLOW.md).

## Install and run

The tested environment is Linux, Python 3.10, NumPy 1.26.4, SciPy 1.15.3 and
NetworkX 3.4.2. The C++ census checker requires a C++20 compiler. The numerical
adapter reads back HiGHS options through SciPy's version-specific interface;
use the pinned requirements. The launcher uses systemd and cgroup v2 to enforce
an aggregate 4 GiB memory limit with swap disabled. It does not impose a time
or node limit. Select a free logical CPU on your machine.

From the companion root, first fetch the authenticated graphs:

```sh
./scripts/fetch_graphs.sh
python3 -m venv lower-environment
lower-environment/bin/pip install -r generation/conditioned-lower-bounds/requirements.txt
```

For example, to run on CPU 6, writing outside the software directory:

```sh
PYTHON="$PWD/lower-environment/bin/python" \
  generation/conditioned-lower-bounds/launch.sh 6 \
  --graphs "$PWD/graphs" --out "$PWD/lower-run" --case all
```

Choose `--case dsjc250`, `dsjc500`, `dsjc1000`, or `c2000` to generate just one
instance's proof. `--stage NAME` runs a named stage and all its dependencies.
The available stages can be listed without running computations:

```sh
python3 generation/conditioned-lower-bounds/run.py --list
```

To resume the same run after an interruption, add `--resume` and use the same
output directory and software environment. Completed stages are reused only
after their source, inputs, producer records and output hashes are checked.
Failed attempts remain in the run directory. Changes to the source or numerical
environment require a new run directory.

Each run preserves a source/input snapshot, exact commands, stdout/stderr,
stage timings, numerical arrays, certificate files and verification receipts.
Only the final exact verification stages populate `verified_lower_bounds` in
the result file. A solver failure or interrupted search supplies no lower bound.

## Check the supplied reproduction

`reference/` contains the proof objects and numerical outputs from the fresh
30 September–1 October 2026 reproduction, including all 96 completed stages.
Check its file hashes with:

```sh
(cd generation/conditioned-lower-bounds/reference && sha256sum -c SHA256SUMS)
```

The independent replay needs Python and a C++20 compiler; it does not run an
LP or MILP solver. Under the same one-core and memory policy:

```sh
systemd-run --user --scope -p MemoryMax=4294967296 -p MemorySwapMax=0 \
  -p TasksMax=64 taskset -c 6 python3 -B \
  generation/conditioned-lower-bounds/verify_reference.py \
  --graphs "$PWD/graphs" --out "$PWD/lower-reference-check"
```

This reconstructs all required families from the graphs and checks the
certificates. C2000.9's size-six family is also regenerated by the separate
C++ census implementation. DSJC500.9's 29,791 lower bound is checked through
46 profiles and 368 packing/profile combinations below that threshold. This
does not resolve the remaining profiles below the known 29,848 upper bound.

## Computational record

The fresh reproduction took approximately 3 h 8 min on one core of an
Intel Core i9-7980XE (2.60 GHz nominal), under a 4 GiB aggregate cap.
The workstation had other workloads on other cores; see [HARDWARE.json](HARDWARE.json)
for the recorded host and allocation details. See [reference/COMPUTATIONAL_RECORD.md](reference/COMPUTATIONAL_RECORD.md)
for stage costs, software versions and accounting scope. These are reproduction
costs after the proof obligations and implementation were prepared. They do
not measure historical discovery or development effort.

The mathematical constructors and branching programs are retained from that
executed implementation. `reference/executed-source-map.json` records their
source hashes and the limited portability edits. The portable scheduler has
its own run records; reference timings are not measurements of a new run through
that scheduler. Log transcripts replace machine-specific paths with `<source>`,
`<run>` or `<python-site-packages>`. C2000.9's census metadata uses a relative
graph path. Certificate payloads and numerical arrays are preserved unchanged.
